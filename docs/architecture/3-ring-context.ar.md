# 🛡️ معمارية الحلقات الثلاث وجدار الحماية السياقي (3-Ring Context Architecture)

أحد أكبر التحديات التي تواجه وكلاء الذكاء الاصطناعي هي مشكلة **تسريب السياق (Context Bleed)**؛ حين تختلط تفاصيل مشروع شخصي بتفاصيل مشروع شركة تجارية، أو حين تتدفق معلومات تسويقية إلى بيئة برمجية صارمة.

لحل هذه المعضلة جذرياً، تبتكر منصة Tidy معمارية **الحلقات الثلاث (3-Ring Context)** المزودة بـ **جدار حماية سياقي حازم (Contextual Domain Firewall)**.

---

## ⭕ نموذج الحلقات الثلاث (The 3-Ring Model)

عند استدعاء السياق بواسطة أمر `tidy context current` أو عبر بروتوكول MCP، يتم تجميع مصفوفة التوجيه بدقة عبر 3 طبقات تركيزية متداخلة:

```
                  ┌────────────────────────┐
                  │    الحلقة الأولى 🟢     │
                  │   سياق النطاق الحالي   │
                  │  Active Project Domain │
                  └───────────┬────────────┘
                              │
                  ┌───────────▼────────────┐
                  │    الحلقة الثانية 🟡    │
                  │  تفضيلات المطور العامة  │
                  │   Developer Profile    │
                  └───────────┬────────────┘
                              │
                  ┌───────────▼────────────┐
                  │    الحلقة الثالثة 🔴    │
                  │  القواعد السيادية الصلبة│
                  │   Sovereign Invariants │
                  └────────────────────────┘
```

### 1. الحلقة الأولى: سياق النطاق النشط (Active Domain Ring)
تحتوي فقط على المعارف، المتغيرات، والأهداف المرتبطة بالمشروع الذي تعمل عليه حالياً (مثلاً: `tidy-agent` أو `pocket-office`). 
- تتبدل محتويات هذه الحلقة فوراً بمجرد تشغيل أمر `tidy context switch <domain>`.
- تمنع كلياً تسريب أي مسارات أو أسماء عملاء من مشاريع أخرى.

### 2. الحلقة الثانية: تفضيلات المطور والمحيط (Developer Profile Ring)
تحتوي على أسلوب عملك الشخصي والمستمر عبر جميع المشاريع:
- لغات البرمجة المفضلة، تفضيلات الـ IDE، نمط كتابة الـ Git Commits.
- صياغة المخرجات (تفضيل اللغة العربية أو الإنجليزية، أسلوب الردود المباشر والموجز).

### 3. الحلقة الثالثة: القواعد السيادية غير القابلة للتفاوض (Sovereign Invariants Ring)
هذه الحلقة تمثل الدستور الأمني للمنظومة:
- حظر كتابة أو تسريب مفاتيح الـ API السرية.
- منع استخدام مسارات عشوائية أو سحابية بديلة عن SQLite SSOT.
- الالتزام الصارم بقواعد العزل الأمني في برمجيات سطح المكتب (`nodeIntegration: false`).

## 🧱 جدار الحماية السياقي (Contextual Domain Firewall)

يعمل جدار الحماية الداخلي كمرشح أمان (Security Interceptor) يعترض استعلامات الاستدعاء:

```javascript
// آلية فلترة الاستدعاء المعرفي
export function filterContextByFirewall(activeDomain, candidateNodes) {
  return candidateNodes.filter(node => {
    // 1. العقد العامة ذات الأهمية القصوى مسموحة دائماً
    if (node.is_global && node.ring === 3) return true;

    // 2. حظر صارم للعقد التابعة لنطاقات أخرى
    if (node.domain && node.domain !== activeDomain) {
      return false; // إسقاط العقدة ومنع تسريبها
    }

    return true;
  });
}
```

### فوائد جدار الحماية
1. **استهلاك اقتصادي للتوكنز (Token Efficiency)**:
   - يمنع حشو نافذة السياق (Context Window) بآلاف التوكنز غير المرتبطة بالمهمة الحالية، مما يقلل التكلفة بنسبة تفوق 60% ويزيد سرعة استجابة النموذج.
2. **تركيز أقصى للنموذج (Maximum Agent Focus)**:
   - عندما يطلب منك الوكيل كوداً لمشروع معين، لا يخلط أبداً بين مكتبات مشروع React ومكتبات مشروع PHP أو Electron.
3. **حماية سرية العملاء**:
   - لا يمكن لنماذج الذكاء الاصطناعي قراءة بيانات عملاء نطاق تجاري أثناء برمجتك لأداة مفتوحة المصدر.

## 🔄 التبديل الفوري بين النطاقات

يمكنك الانتقال بلحظة واحدة بين مساحات عملك:

```bash
# الانتقال إلى سياق مشروع الواجهات
tidy context switch "qahera-ui-kit"

# فحص السياق النشط حالياً وجدار الحماية
tidy context current
```
بمجرد التبديل، يتم إخطار خادم MCP تلقائياً بتحديث المورد الحي `tidy://context/current`، لتبدأ بيئة التطوير فوراً بالعمل بالسياق الجديد بدون الحاجة لإعادة تشغيل الـ IDE!
