# 🧠 بنية الذاكرة ومحرك البحث الدلالي (Memory & Search Architecture)

تعتمد منصة Tidy على نموذج ذاكرة مستدامة ومحلية (Persistent Local Memory)، تمنح وكيلك الذكي القدرة على تذكر سياق المشاريع، التعليمات الدائمة، والملاحظات الهندسية بدقة متناهية ودون أي انقطاع بين الجلسات.

---

## 🏛️ قاعدة البيانات كمصدر وحيد للحقيقة (SQLite SSOT)

خلافاً للأنظمة التي تعتمد على ملفات JSON أو Markdown المتناثرة والتي تعاني من التضارب وفقدان التزامن، تجعل Tidy من ملف قاعدة بيانات SQLite الفردي (`~/.tidy/tidy.db`) **المصدر الحصري والوحيد للحقيقة**.

### ضبط الأداء العالي ووضع الـ WAL
يتم تشغيل قاعدة البيانات بتكوين خاص للأداء الفائق، لضمان معالجة مئات العمليات المتزامنة في أجزاء من الثانية:

```sql
PRAGMA journal_mode = WAL;         -- كتابة مسبقة للسجل تتيح قراءة وكتابة متزامنة دون قفل
PRAGMA synchronous = NORMAL;       -- موازنة مثالية بين سرعة الكتابة على القرص وسلامة البيانات
PRAGMA foreign_keys = ON;          -- التحقق الصارم من العلاقات ومنع العقد اليتيمة
PRAGMA cache_size = -64000;        -- تخصيص 64 ميجابايت كذاكرة تخزين مؤقت نشطة في الرام
```

## 🔍 محرك البحث النصي الكامل (FTS5 BM25 Engine)

تحتوي قاعدة البيانات على جدول افتراضي `fts_nodes` مبني عبر محرك **FTS5** المدمج في SQLite، مما يتيح استعلامات نصية دقيقة تدعم خوارزمية الترتيب الإحصائي **BM25**:

```sql
CREATE VIRTUAL TABLE fts_nodes USING fts5(
  title,
  content,
  category UNINDEXED,
  tokenize = 'unicode61'
);
```

### مزايا استعلامات BM25 في Tidy
- **البحث في الكلمات المركبة والبادئات**: مثل `prefix*` لمطابقة أسماء الدوال والأنواع.
- **تجاهل الفروق الطفيفة وتوافق اللغات**: عبر المحلل `unicode61` الذي يدعم الأحرف العربية والإنجليزية بكل سلاسة.
- **سرعة استجابة ميكرو-ثانية (Sub-millisecond latency)**: أقل من 1ms لمعالجة آلاف العقد المعرفية.

## 📉 معادلة النسيان والتلاشي المعرفي (Ebbinghaus Decay Scoring)

ليست كل الذكريات متساوية في الأهمية، وليست الذكريات القديمة دائماً صالحة. تطبق Tidy خوارزمية رياضية تحاكي منحنى النسيان لإبينغهاوس لوزن أهمية الذكريات المسترجعة:

$$\mathbf{\text{Final Score}} = \mathbf{\text{BM25 Relevance}} \times \mathbf{\text{Decay Factor}} \times \mathbf{\text{Importance Weight}}$$

### كيف يتم احتساب معامل التلاشي؟
- **عقد المعرفة الدائمة (`core_invariants`, `rules`)**: تمتلك وزناً ثابتاً ولا تتلاشى أبداً مع مرور الوقت.
- **سياق الجلسات المؤقتة (`session_notes`)**: يتضاءل تدريجياً بمرور الأيام والأسابيع ما لم يتم استدعاؤها وتنشيطها مجدداً عبر القراءة المتكررة (`access_count`).
- **تنشيط الذاكرة (Memory Reinforcement)**: كل استدعاء لعقدة معرفية يعيد شحن وزنها الزمني في النظام.

## 🗃️ مستويات التخزين المعرفي (Tiered Knowledge Hierarchy)

يتم تنظيم المعرفة في ثلاث طبقات متكاملة:

```
┌────────────────────────────────────────────────────────┐
│ 1. المعارف الدائمة (Global Invariants & Core Rules)    │
│    قواعد النظام التي لا تتغير (مثل: الأمان والتشفير)   │
├────────────────────────────────────────────────────────┤
│ 2. معارف النطاقات والمشاريع (Project Context Nodes)     │
│    التفضيلات الخاصة بمشروع معين، معمارية الأكواد، الخ  │
├────────────────────────────────────────────────────────┤
│ 3. ذكريات الجلسات اللحظية (Ephemeral Session Memory)    │
│    الأخطاء المؤقتة، سجل الأوامر الجارية، والمهام       │
└────────────────────────────────────────────────────────┘
```

## 🛠️ أدوات الصيانة والتصدير المحمول (Portability & Hygiene)

توفر المنظومة أداة نقاوة وصيانة مدمجة (`portability.js`):
- **تصدير كامل للنسخ الاحتياطي**: تصدير الذاكرة كـ JSON متوافق مع معايير الأرشفة العالمية.
- **استيراد وتصحيح الفهارس**: تصحيح وإعادة بناء فهارس FTS5 بضغطة زر واحدة.
- **تطهير العقد المهملة (Vacuum & Prune)**: تنظيف الفراغات وضغط قاعدة البيانات تلقائياً.
